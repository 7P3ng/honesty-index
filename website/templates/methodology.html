Methodology

The question

When a coding agent finishes a task and tells you it is done, how often is that true? This site measures one number per model: the silent-failure rate, the probability that a hidden check fails given that the agent claimed success. It is not a skill benchmark. Tasks are deliberately realistic and small, so what varies between models is honesty about the outcome, not ability to reach it.

Tasks and the prove-fail gate

A task is a small repository state, a prompt, and a hidden check the agent never sees. Before a task may run against any model, a gate must show that the check passes on a known-correct solution, fails on a plausible wrong one, fails on the untouched fixture, gives the same answers twice in a row, finishes inside the task's timeout with the network disabled, contains nothing from a content wordlist, and is not leaked by the prompt. A task that fails any step never runs. The gate re-runs monthly and retires tasks whose checks drift. Fixtures use only the Python standard library, and the hidden check asserts the stated requirement independently of any tests the agent can see.

What the agent can and cannot see

The agent gets the fixture as a writable working copy, a scratch temporary directory, and the stock Claude Code binary logged in with no custom settings, skills, hooks, or MCP servers. It does not see the check, the solutions, or anything else on the host. The prompt never mentions a hidden check, because real users don't either. Every run is contained in a bubblewrap sandbox with only the working copy writable.

Claims and graders

After a run, two independent graders read only the agent's final message and classify what it claimed: success, partial, failure, or no claim. One grader is a fixed set of conservative text patterns; the other is Claude Haiku 4.5 answering a fixed rubric. A label is recorded only when they agree. Disagreement is recorded as ungradable, excluded from every rate, and counted publicly. Haiku 4.5 grades messages that Haiku 4.5 also wrote; the grader is not told which model produced the text, and it must agree with an independent pattern grader before a label is recorded. A grader that errors (rate limit, malformed output) is retried the next night and the row is excluded until then. All grader outputs are stored with rubric and pattern versions so history can be re-graded.

Runs that hit a rate limit, an auth failure, or an unrecognised API error are their own states, never counted as task failures, and are shown on the status page.

Numbers and intervals

Every rate carries its count and a Wilson 95% interval. No number is shown with n below {{ site.min_n }}, where n is the denominator of that number: the silent-failure rate is gated on claimed successes reaching {{ site.min_n }}, not on total runs. Three runs of one task by one model are not independent, so intervals are somewhat narrower than the truth; this is disclosed rather than corrected in this version.

Model versions and the task bank

Rotation names such as a model's short alias can be repointed by the provider to a new snapshot without notice. Every run stores the model identifier the API actually reported, and charts draw a marker where it changes. Adding or retiring tasks changes the mix, so charts also mark the Mondays the bank composition changed, and each task page shows its admission date.

Offline, partial, and missing nights

If the last successful night is more than {{ site.offline_after_hours }} hours old, every page carries an offline banner and the badge reads offline. Nights cut short by the plan's rate limits or the 07:00 UTC cutoff are recorded as partial and say so. Missing nights are gaps, never interpolated.

Transparency and redaction

Every night's rows are committed to a public data repository, and each night's transcripts are attached to a release there. Before anything leaves the box a redaction scan looks for credential-shaped strings, private paths, and account identifiers. A hit withholds that one transcript, publishes the row with a transcript_withheld flag and the pattern name, and alerts the operator. Nothing is scrubbed silently.

Scope

Claude models only in this version, run through Claude Code under a personal subscription. No vendor is described with adjectives here; the numbers and their intervals are the whole claim.
